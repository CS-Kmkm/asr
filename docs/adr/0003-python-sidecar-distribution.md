# ADR-0003: Pythonサイドカーワーカーの配布方式

## ステータス

提案 — 未決定 (2026-06-13)

## 文脈

本プロダクトのASR処理はPythonサイドカーワーカー (`asr_worker`) が担う。
このワーカーは以下の依存関係を持つ。

- Python 3.10〜3.13
- PyTorch (CUDA対応版): torch + torchvision + torchaudio のCUDAホイールは
  合計で **数GB** に達する
- transformers (Hugging Face)
- bitsandbytes (4bit/8bit量子化用)
- その他の推論ライブラリ

エンドユーザーへの配布時に、これらの依存関係をどのように提供するかが未決定である。

## 検討している3案

### 案①: Python埋め込み + PyInstaller製サイドカーEXE同梱

Pythonランタイムと依存ライブラリをPyInstallerでバンドルし、
単一の実行ファイル(または展開ディレクトリ)としてTauriアプリに同梱する。

### 案②: 初回セットアップでPython環境自動構築

アプリ初回起動時またはセットアップウィザード内で、
Python環境(uv / condaなど)を自動的にダウンロード・構築する。

### 案③: 推論をRust側に移してPython排除

ASR推論をRustネイティブの推論ライブラリ (candle, ort, whisper.cpp バインディング等) で
実装し、Pythonサイドカーを排除する。

## 比較表

| 評価軸 | 案① PyInstaller EXE同梱 | 案② 初回セットアップ自動構築 | 案③ Rust推論・Python排除 |
| --- | --- | --- | --- |
| 導入容易性 | 高: ダウンロード後すぐ起動できる | 中: 初回に数分〜数十分の待機が発生する | 高: 単一バイナリに近い構成になる |
| 配布サイズ | 非常に大きい: torch+CUDAで数GB超 | 小: アプリ本体は小さく、依存は後からDL | 小〜中: モデルファイルのみ |
| 失敗モード | インストーラーDL失敗、展開エラー | ネットワーク障害、権限不足、競合するPython | ライブラリ未対応モデル、CUDA互換性問題 |
| 保守性 | 低: torch更新のたびに再バンドルが必要 | 中: 依存更新はpip/uvで分離できる | 低〜中: Rustライブラリのモデル対応状況に依存 |
| モデル対応幅 | 高: transformersエコシステム全体 | 高: transformersエコシステム全体 | 低: 対応モデルが限られる |
| GPU対応 | 案②と同等 | CUDAホイールを自動選択できる | candleはCUDA対応。ort (ONNX) はDirectML経由も可能 |

## 推奨案(暫定)

**案②(初回セットアップで自動構築)を推奨候補とする**が、正式決定には至っていない。

推奨理由は以下のとおりである。

- torch + CUDAホイールが数GBに達するため、案①のインストーラーへの同梱は現実的でない
- 案②はアプリ本体を小さく保ちながら、transformersエコシステム全体を活用できる
- uv などの高速パッケージマネージャーを使えば初回構築時間を短縮できる

案③はモデル対応幅が現時点では狭く、VibeVoice-ASR-HFなどのHugging Face専用モデルへの
対応が難しい。将来的にcandleやortのモデルサポートが拡大した場合は再評価する。

## 決定前に検証すべき事項

- 案②: uv等を使った環境構築の所要時間とユーザー体験の評価
- 案②: 既存Pythonインストールとの競合リスクの調査
- 案①: PyInstallerでのtorch+CUDA同梱の実現可能性と実際のサイズ計測
- 案③: candleまたはortでVibeVoice-ASR-HF相当モデルを動作させられるか検証
