# ADR-0003: Python サイドカーワーカーの配布方式

## ステータス

決定済み（2026-10-23）。初回セットアップ時に uv で環境を構築する方式を採用する。
実装後のインストーラー・GPU 実機確認は issue #44 の受け入れ確認として別に行う。

## 決定

Tauri の resource に `asr_worker` の Python ソース、`pyproject.toml`、`uv.lock`、
`.python-version` を同梱する。Python、モデル、CUDA 依存はインストーラーへ同梱しない。
uv は利用者がインストールする前提とし、PATH または `ASR_UV` から起動する。
uv 自体の自動ダウンロード・任意のインストールスクリプト実行は行わない。

初回の明示的なモデル読み込みで `uv sync --frozen --no-dev --python 3.12` を実行し、
環境をアプリの local data 内の `worker-runtime/<app-version>` に作成する。
保護されたインストール先に venv を書き込まない。VibeVoice 選択時のみ `vibevoice`
extra を有効にする。各ワーカー起動前にロックとの整合を確認し、以降は uv のキャッシュと
インストール済みパッケージを再利用する。初回はネットワークと十分な空き容量が必要となる。

Setup と Models の読み込み UI に環境準備中の表示を出す。セットアップの失敗は
ネットワーク・容量・権限の確認を案内し、uv 不在はインストールまたは `ASR_UV` の指定を
案内する。環境準備と hello はキャンセル・アプリ終了・設定変更による割り込みを受け付ける。

ワーカーは選んだ resource のディレクトリを cwd として起動する。起動後の `hello` で
protocol version と worker/app version の一致を検証し、合わなければモデルをロードしない。
配布版の resource がある場合は、隣接した別チェックアウトのワーカーより優先する。
開発版は exe の祖先のチェックアウトを優先し、cwd の探索は debug ビルドに限定する。
明示的な `ASR_PYTHON` は開発・管理環境向けの上書きとして残す。

## 選択理由

PyInstaller による GPU 依存の同梱はインストーラーを大きくし、更新ごとの再配布が必要になる。
Rust の推論ライブラリへの全面移行は、現在のモデル対応を維持するための変更が大きい。
uv による分離環境は、既存の開発用ロックを配布にも使え、依存の構築を同じ手順にできる。

## 検証と制約

自動テストでは配置先・引数・秘密を含まない失敗・バージョン不一致を確認する。
実機では uv のある新規ユーザープロファイルで、インストール、初回環境構築、モデル取得、
録音から文字挿入までを確認する。CUDA の初回ダウンロードサイズや実時間は未測定であり、
この決定で KPI 達成やすべての GPU 構成への対応を主張しない。
