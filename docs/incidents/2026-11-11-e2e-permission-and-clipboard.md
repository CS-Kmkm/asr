- Symptom [stated]: Computer Use app approval first timed out for the Python measurement fixture. Its log ends with `owned fixture closed` followed by `could not open clipboard` during the finally restore. Evidence: `.ai/issue-88/e2e-20261111/passive-run-v2/` and its sibling log.

- Permission cause [unresolved]: The exact security-software rule and whether it caused each input interruption were not inspected. The user's required startup order is an operational prerequisite, not proof of a particular security product's fault.
- Non-causes [derived]: This failed measurement does not establish an ASR accuracy/latency regression or a defect in the product's own insertion/clipboard implementation. The failed restore was the measurement companion's cleanup path.
- Decision [decision]: Treat permission handling as a user step before audio playback. Verify real recording, not merely receipt of a toggle shortcut. Never automate security/permission dialogs or bypass the Computer Use input guard.
- Decision [decision]: The revised passive observer never writes the clipboard or exports pasted text. During insertion/restore it polls only the clipboard sequence number. After a distinct native EDIT change and at least 250ms without a sequence change, it reads for an in-memory original-text comparison; contention is retried, not fatal. Original-text return plus the distinct native EDIT change provides an observed upper bound, not an internal verification timestamp or proof of clipboard paste. This removes the companion's stale-owner restore and history/sync write paths. Unrelated clipboard activity invalidates the trial's attribution.
- Fix boundary [derived]: Playback is tagged by trial and cannot overlap rearming; unexpected hotkeys/timeouts latch a desynchronized state until the operator verifies app idle. A separate play command follows verified recording/security completion.
