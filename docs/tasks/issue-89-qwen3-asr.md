Goal: Add Qwen3-ASR 0.6B / 1.7B as selectable Japanese-centred models (multilingual, dictionary terms as a prompt) on the existing Windows-native runtimes, measure them on this machine against the current Japanese candidates, and record under which conditions Qwen3 is recommended as a manual preset (issue #89).

Scope / non-scope:
- In scope: Qwen3-ASR 1.7B on `transformers-asr` (CUDA bfloat16, pinned `Qwen/Qwen3-ASR-1.7B-hf`); Qwen3-ASR 0.6B and 1.7B Q8_0 GGUF on `speech-cpp` (Vulkan); speech.cpp per-model rules (weight type, Japanese-only check, prompt) taken from the pinned table and cross-checked with the catalog; catalog entries for all four backend x size pairs; Rust validation / model identity / cache-removal guard and the Models page derived from the catalog; Japanese evaluation on the #86 holdout plus a long-form check; a manual preset recommendation.
- Non-scope (brief, 2026-11-12): Qwen3 "streaming" (vLLM, Linux only), stateful streaming (#82), default-model change, automatic switching during recording, NeMo / WSL, Q4_K GGUFs (not exposed: Q8_0 1.7B already fits in 4.7 GB device-wide; Q4_K would double the matrix for a saving the 12 GB GPU does not need), a new mixed-language audio set.

Constraints: Windows-native only. Every model file pinned by revision, size and SHA256, fetched only by an explicit load, re-verified on every load; no fallback model, cloud call or unpinned download. Vulkan is never labelled CUDA. Evaluation is Japanese-only (user rule): no pure-English set; Japanese speech containing English terms counts as Japanese. No fabricated audio. Transcripts are not committed. Network for this task: `gh issue view 89` and each pinned model download once (no web search).

Design:
- `asr_worker/speech_cpp.py` `MODELS` entries carry `weight_type`, `japanese_only` and `prompt`. Load requires the server to report exactly the pinned weight type on `Vulkan0`; `transcribe` refuses non-Japanese locales only for Japanese-only models and sends the dictionary prompt only to models that take one. Haas / Parakeet: Japanese only, no prompt (the server refuses a `prompt` option for them). Qwen3-ASR: `language` = locale base code (none = automatic detection), `prompt` = the app's rendered dictionary prompt. Verified against the running speech.cpp 0.10.1 server: `/v1/models` lists `language` (30 languages incl. ja, "steers") and `prompt` ("steers") options, both multipart fields are accepted (HTTP 200), an unknown language is refused with HTTP 400. Model identity `speech.cpp:<id>:<weight_type>`. GGUF provenance reported by the server matches `Qwen/Qwen3-ASR-0.6B@5eb144179a02acc5e5ba31e748d22b0cf3e303b0`.
- `asr_worker/transformers_runtime.py` adds `QWEN3_ASR_1_7B` (7 files, 4,087,628,216 bytes; processor/tokenizer files identical to 0.6B, own `config.json`). CUDA OOM maps to `gpu_oom` through the shared mapping; there is no CPU retry.
- Catalog (`src/asr-model-catalog.json`): `speech-cpp:qwen3-asr-{0.6b,1.7b}` (multilingual, `vulkan`, vocabulary `prompt`, Q8_0, single pinned GGUF) and `transformers-asr:qwen3-asr-1.7b`; the planned 1.7B placeholder is removed. `decoderOnCpu` is false for the Qwen GGUFs: the server reports the whole model on `Vulkan0`; the decoder placement is not separately documented by the runtime (inference).
- Rust: the Japanese-only locale check uses the selected pinned model's `languageScope` for every pinned backend (no blanket speech.cpp rule); speech.cpp model-ID validation uses the generic pinned-model message; the loaded identity and cache-removal guard use the catalog weight format. Models page: the locale block and the backend detail text follow the selected model; Qwen on speech.cpp shows a multilingual Vulkan (not CUDA) detail.

5. Recommendation (manual preset only; the app default stays faster-whisper; no switching during recording):
   - General Japanese dictation: keep Haas-ja (best CER 4.32%, about 65 ms warm, 2.8 GB device peak). Qwen3 does not beat it on the holdout or the long-form check.
   - Recommend Qwen3-ASR 1.7B Q8_0 on speech.cpp when the user needs a multilingual-capable model in the Japanese-centred slot (an explicit non-Japanese speech language, which Haas / Parakeet / ReazonSpeech refuse; the automatic setting is accepted by all of them) or a model that accepts dictionary context: it is the most accurate measured multilingual option on Japanese after Whisper on short clips (5.93% vs 4.78%), matches Haas and beats Whisper on the long-form check (4.62% vs 9.41%), runs about 0.3 s warm per short clip on Vulkan and fits in about 4.7 GB device-wide. Keep the dictionary app-scoped and short: an unrelated term list raised CER by 0.3–0.8 points.
   - Qwen3-ASR 0.6B (either runtime) is not recommended: no accuracy gain over Haas / Whisper, and the transformers runtime is 9x slower than speech.cpp at the same accuracy. Prefer speech.cpp over transformers for Qwen3 on this machine.
   - Whether Qwen3 helps on Japanese speech with English terms remains open until such recordings exist (needs a human reading `scripts_mixed.md`).
