# 実機検証チェックリスト（#74・#75・計測/構造改善）

> 対象: 開発者本人（Windows 11 実機、フォアグラウンドを持つ対話端末から実施）
> 目的: エージェントからは実行できない実機確認（フォアグラウンド入力、マイク、IME、WebView2 描画、GPU、実プロバイダー）を一か所にまとめる。
> 本書は手順であり、合格結果ではない。各項目を PASS / FAIL / 未確認で記録し、FAIL は再現手順と History の `insertion_detail` を添える。

共通の注意:
- 既存の History・音声・ベンチ結果を上書きしない。ベンチ出力は新しいパスへ保存する。
- 計測は warm/cold を分け、各条件 5 回以上（可能なら 10 回）。p50 を段階ごとに足し合わせない。
- 文字起こし本文・ウィンドウタイトルをログやメモに貼らない。
- 共通セットアップと挿入の基本確認は [docs/windows_verification.md](../windows_verification.md) に従う。

## A. #74 停止→挿入の待ち時間（stop-to-insert-latency-fixes）

| ID | 確認内容 | 手順 | 期待結果 |
|---|---|---|---|
| A-1 (F1) | 空の変換範囲を非アクティブとして扱う | 開発系アプリ（VS Code 等）で IME オン・未変換状態のまま Dictate | `ime_active` で待たされずに挿入される。変換中に止めた場合は従来どおり待つ |
| A-2 (F2) | 1 秒後の「未準備」ヒント | 挿入先が準備できない状態（変換中など）で停止 | 約 1 秒後にオーバーレイの処理表示内にヒントが出て、状態が変わると消える |
| A-3 (F3) | 最後の入力時刻からの静穏待ち | 停止直後に数回キー入力してから止める | 最後の入力から約 350 ms で挿入される（入力開始から数え直さない） |
| A-4 (F4) | helper 終了の非同期化 | 連続で 3 回 Dictate | 2 回目以降の受付が helper 終了待ちで遅れない。挿入結果は変わらない |
| A-5 (F5) | 最終一括挿入では AI 前のキー待ちをしない | ライブ挿入 OFF、ショートカットを押したまま停止 | AI 補正はすぐ始まり、キーを離すまで貼り付けはされない |
| A-6 (F6) | ライブ字幕 | ライブプレビュー ON で 10 秒以上話す | 字幕がオーバーレイにだけ表示され、録音表示の時点で領域が確保されている（表示が跳ねない） |
| A-7 (F7) | 停止の先行通知 | 長めに話して停止 | 停止後に余分なライブ decode が走らない（体感で停止→処理開始が速い） |

## B. #75 残りの高速化（remaining-latency-improvements）

| ID | 確認内容 | 手順 | 期待結果 |
|---|---|---|---|
| B-1 (A1) | 16 kHz PCM16 の直接読み込み | faster-whisper で 3 秒・30 秒を各 5 回 | 認識結果が従来と同等。エラーやフォールバック多発がない |
| B-2 (A3) | Faster live preview（既定 OFF） | Privacy の「Faster live preview」を ON/OFF で比較 | ON でプレビューが軽くなり、最終結果は OFF と同等 |
| B-3 (A4) | 新音声ゲート | 長い連続発話（60 秒以上）とポーズ多めの発話 | プレビューが途切れず、CPU 使用率が従来より低い傾向 |
| B-4 (N1) | クラウド ASR 接続の再利用 | cloud ASR で 60 秒以内に連続 3 回 | 2 回目以降の待ちが短い。接続再利用の判定は通信観測で行い、体感だけで判断しない |
| B-5 (S1/S2) | 保存・次回受付 | 連続 Dictate の直後に History・Dictionary ページを開く | 最新の項目が表示される。Delete all 直後に古い記録が復活しない |
| B-6 (U1) | GPU 診断の並行化 | GPU あり／nvidia-smi なしの各環境で起動 | 起動が診断待ちで止まらない。診断結果は従来どおり表示 |
| B-7 (U2) | `uv sync` 省略と修復 | 通常起動 → 依存を壊す（.venv のパッケージを 1 つ削除）→ 起動 | 通常時は sync を省略し、壊れた環境では 1 回修復して起動する |
| B-8 | 選択テキスト翻訳の非同期化 | 選択テキスト翻訳を連続実行 | UI が固まらず、置換結果は従来どおり |
| B-9 | 録音開始の重ね合わせ | 録音開始を 10 回 | 開始音から録音開始までが短くなり、取りこぼしがない |
| B-10 (W4) | Ask の回答ストリーム表示 | Ask を実行し、途中でキャンセルもする | 回答パネル（WebView2）に逐次表示され、確定時に置き換わる。キャンセルで消える |

## C. 計測/構造改善（measurement-and-structural-latency）

増分の最終文字起こし（A5）は既定オン、投機的な AI 修正（C3）は既定オフ。C-1・C-2 は A5 を OFF にして行い、従来と動作が変わらないことを確かめてから ON に戻す。

| ID | 確認内容 | 手順 | 期待結果 |
|---|---|---|---|
| C-1 (M1) | 録音ごとの区間記録 | Dictate・Translate・Edit・Ask を各数回。うち1回は録音中に取り消し、1回は停止後の処理中に取り消し、1回は挿入できない欄（パスワード欄など）で実行。その後 Diagnostics の「Copy diagnostics」 | 結果ごと（pasted / clipboard_only / cancelled:recording など）に件数と区間ごとの p50/p95、欠けた区間数が出る。本文・ウィンドウタイトル・take id が含まれない |
| C-2 (S2) | History 保存の後回し | Dictate 直後に History と Dictionary ページを開く。AI 修正 ON で辞書候補が出る発話も試す | 最新の項目と辞書候補が表示される（遅れても数秒以内に自動更新）。完了表示や次の録音開始が遅れない |
| C-3 (S2) | 削除との競合 | Dictate の完了直後に Delete all、別の回で History を OFF | 削除後に、直前の回の行・音声・辞書候補が復活しない |
| C-4 (A5) | 増分の最終文字起こし（Settings の「増分の最終文字起こし」） | ローカルモデルで 30 秒・60 秒・90 秒をポーズを挟んで話す。同じ内容を OFF でも行う | ON で停止→文字起こしが短く、文字が OFF とほぼ同じ。話し続けた（ポーズなし）場合も文字が欠けない |
| C-5 (A5) | フォールバック | 録音中に辞書を編集する、またはクラウド ASR で ON にする | 録音全体の認識に戻り、結果は従来どおり。Diagnostics の `asr_incremental` に理由コードが記録される |
| C-6 (A5) | 録音中の負荷 | ON でライブプレビューを見ながら 60 秒以上話す | プレビューが極端に止まらない。GPU/CPU 使用率の増え方を記録する |
| C-7 (C3) | 投機的な AI 修正（AI 修正設定の「投機的なAI修正（実験的）」） | ライブプレビュー ON・AI 修正 ON で短文を 10 回 | 一致した回は文字起こし後の待ちが短い。結果の文面は OFF と同等。Diagnostics の `speculative_correction` で hit/miss、`live_final_match` で一致率を確認 |
| C-8 (C3) | 取り消しと自動モード | 停止直後に取り消す。自動モード判定で Edit/Ask になる発話をする | 取り消しは従来どおり。別モードに回った場合は投機結果が使われない（`miss_mode`） |
| C-9 (M2) | ベンチの本番条件 | [docs/benchmarks.md](../benchmarks.md) の新しいオプション（`--dictionary-csv`、`--idle-gap-s`、`--live-preview` など）で warm/cold・idle 後・ライブ競合ありを計測 | 結果 JSON に条件と device/compute type が記録される。新しい出力パスに保存する |
