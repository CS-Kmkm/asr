Goal: Second stage of issue #87 — a small runtime-adapter abstraction in the Python worker plus two new Windows-native runtimes, so a new runtime/model pair is added without touching the UI, recording or insertion pipelines: sherpa-onnx (ONNX Runtime, CPU and CUDA execution providers) with ReazonSpeech k2 v2, and transformers on torch CUDA with Qwen3-ASR 0.6B.

Scope / non-scope:
- In scope: `asr_worker/runtime_adapter.py` (pinned-file acquisition and verification, device policy, audio reading, long-audio splitting, native-log capture, shared load/transcribe/unload/cancel/error mapping); `asr_worker/sherpa_onnx_runtime.py` (backend `sherpa-onnx`, offline transducer, model `reazonspeech-k2-v2`); `asr_worker/transformers_runtime.py` (backend `transformers-asr`, model `qwen3-asr-0.6b`); worker registration and health `runtime` / `deviceName`; uv extras `sherpa-onnx` and `transformers-asr`; catalog `runtimes` and model entries; Rust backend IDs, settings validation (pinned model IDs, Japanese-only locale), worker command (default model, `ASR_DEVICE`, per-backend `--extra` provisioning, 16 kHz capture), health parsing, load-error messages; Models page selection, speech device, details (Japanese strings); tests; a real GPU smoke of both runtimes.
- Non-scope (user decision 2026-11-11): NeMo, WSL, Docker; online/stateful streaming (#82); Qwen3-ASR 1.7B, speech.cpp Qwen3 GGUF, mixed-language evaluation and presets (#89); Nemotron (stays planned); automatic model selection or default-model change; cache status/delete UI for the new runtimes (speech.cpp only, as in stage 1); hotword biasing for ReazonSpeech; #86-set model comparison and profiles. The main checkout's uncommitted work is untouched.

Constraints: Windows-native only. Model files are fetched only by an explicit load (Load button or the first recording that prepares the selected model), from a pinned revision, with every file's size and SHA256 pinned and re-verified on every load; mismatches are refused and preserved; no fallback to another model, a cloud API or an unpinned download; `from_pretrained` runs with `local_files_only`. CUDA is reported only for what actually ran. Existing faster-whisper, VibeVoice, OpenAI-compatible and speech.cpp behavior and their resolved dependency sets stay unchanged. Agent-facing text English; UI strings get Japanese translations. One backend per worker process: the sherpa-onnx CUDA 12 / cuDNN 9 DLLs and torch's cu130 cuDNN cannot be loaded into the same process (observed: torch import fails with WinError 127 on `cudnn_cnn64_9.dll` after the sherpa CUDA DLLs were preloaded).

Design:
- `RuntimeAdapter(ProgressReporting)`: class attributes `backend_name`, `display_label`, `install_extra`, `models` (`ManagedModel`: repo, revision, `PinnedFile` name/sha256/size, license, `japanese_only`, `kind`), `default_model`, `supported_policies`; hooks `_import_runtime`, `_open(model, paths)` (build + warm-up, set `device`/`compute_type`/`runtime_label`/`device_name` from what ran), `_recognize(samples, rate, language, prompt)`, `_close`; `preload_runtime` is called by the worker's input thread on Windows before the first load (a first torch import hung the worker otherwise, as NumPy did earlier). Errors: `invalid_model`, `invalid_device`, `backend_unavailable` (names the extra), `hf_download_failed`, `model_artifact_invalid`, `cuda_unavailable`, `gpu_unsupported`, `gpu_oom`/`cpu_oom` via `map_backend_exception`, `language_unsupported`, `audio_unsupported`, `cancelled`, `transcript_truncated`.
- Files: `ASR_MANAGED_MODEL_HOME` (default `%LOCALAPPDATA%/LocalVoice/models`)`/<backend>/<model>/<revision>/<file>`; staging names `.download-<pid>-*`, hard-link no-clobber publication, OS trust store via truststore (TLS-inspecting security software on this machine rejects certifi-only verification intermittently).
- sherpa-onnx: `ASR_DEVICE` auto/cuda try the CUDA provider after preloading the pip CUDA 12 / cuDNN 9 DLLs. CUDA is accepted only when (a) the captured native log has no "Fallback to cpu"/"Failed to enable CUDA", (b) `onnxruntime_providers_cuda.dll` is loaded, and (c) `nvidia-smi --query-compute-apps` lists this PID (unknown when nvidia-smi is unavailable; then (a)+(b) decide). auto then rebuilds on CPU and reports `cpu_fallback`; cuda fails with `cuda_unavailable`. Audio over 25 s is split at the quietest 100 ms frame of the last 8 s of each window (ReazonSpeech k2 accepts about 30 s); cancellation between chunks. Prompt is not used (dictionary applied after recognition). Online recognizers for #82 become a new `ManagedModel.kind` with its own builder/session object; acquisition, device policy and errors are reused.
- transformers-asr: `Qwen/Qwen3-ASR-0.6B-hf` (official transformers conversion by the Qwen organisation) through `Qwen3ASRForConditionalGeneration`; CUDA bfloat16 for auto/cuda (`gpu_unsupported` without CUDA, no silent CPU), CPU float32 only for `ASR_DEVICE=cpu`. Language forced from the locale's base code (auto-detect for none); dictionary terms passed as the context prompt; per-token cancel via stopping criteria; token budget as VibeVoice (`transcript_truncated`).

Dependencies and pins:
- `sherpa-onnx==2.0.1` (≥1.13.4 as required for later Nemotron work). Windows x64 CPython 3.12 uses the maintainer's CUDA wheel `sherpa_onnx-2.0.1+cuda12.cudnn9-cp312-cp312-win_amd64.whl` from `huggingface.co/csukuangfj2/sherpa-onnx-wheels` at commit `a095349253fe0776ec06c8f8fa7fb3bc572c0589` (linked from k2-fsa.github.io/sherpa/onnx/cuda.html; SHA256 `054018f0f9faba420d7be1f3cc6278ab5d0c7c767ae597775fbdd9a6a62a9fed`, also locked by uv; ONNX Runtime 1.24.4); other platforms use the PyPI CPU wheel. NVIDIA runtime wheels (Windows): cuda-runtime 12.9.79, cublas 12.9.2.10, cufft 11.4.1.4, curand 10.3.10.19, cuda-nvrtc 12.9.86, cudnn 9.27.0.42 (+ nvjitlink 12.9.86).
- `transformers-asr` extra: `transformers==5.15.1` (has `qwen3_asr`, still accepts the locked tokenizers 0.22.2), `torch==2.11.0` (cu130 index as before), accelerate, librosa, truststore. The `qwen-asr` package was not used: it pins transformers 4.57.6 and pulls gradio/flask. `[tool.uv] conflicts` separates `transformers-asr` from `decision` (transformers==5.10.2) and `vibevoice`; `vibevoice` gained the upper bound `transformers<5.11` because the forked lock otherwise moved its resolution from 5.10.2 to 5.15.1. `uv export --frozen` of the base, `vibevoice`, `decision`, `serve` and `vibevoice+decision` sets is identical before and after. Consequence: the torch-based decision model (automatic voice mode) cannot share the worker with `transformers-asr` (conflicting extras) or with `sherpa-onnx` once it loaded its CUDA DLLs. Settings validation rejects automatic voice mode with `transformers-asr` or with `sherpa-onnx` unless the speech device is explicitly CPU (`decision_asr_runtime_conflict`, Japanese message); the Models/Settings pages disable the combination; the worker additionally refuses `load_decision` after the sherpa CUDA libraries were loaded (`decision_runtime_conflict`).
- Models: ReazonSpeech k2 v2 `reazon-research/reazonspeech-k2-v2@291488c8151be24d7da4bf7af26e533fad96e407`, Apache-2.0, fp32 encoder/decoder/joiner + tokens.txt, 614,881,553 bytes. Qwen3-ASR 0.6B `Qwen/Qwen3-ASR-0.6B-hf@7f1569a48a89f3e3f4dc3a5c9d28bddd903bc76c`, Apache-2.0, 7 files, 1,576,363,223 bytes. Per-file SHA256 in the worker modules and the catalog (cross-checked by test).
