Goal: Give the app one capability-based ASR model catalog (first slice of issue #87) so model metadata, capability display, provenance and managed-model cache handling come from a single source instead of being hard-coded per screen.

Scope / non-scope:
- In scope: a shared catalog file (`src/asr-model-catalog.json`) describing implemented models/backends (faster-whisper default, VibeVoice, OpenAI-compatible, speech.cpp Haas-ja-v1.0 and Parakeet Japanese) and planned entries (Qwen3-ASR 0.6B/1.7B, Nemotron streaming) marked unavailable; capability fields (inference modes batch / chunked / stateful_streaming, language scope Japanese-only vs multilingual, runtime CPU/CUDA/Vulkan/remote, vocabulary adaptation, word timestamps, cancellation granularity, capture sample rate, license, source/revision/SHA256/size for pinned artifacts, measured memory only where a recorded measurement exists); Rust validation of speech.cpp model IDs derived from the catalog; Python test that the catalog matches the pinned `asr_worker/speech_cpp.py` artifacts; Models page display of the selected model's capabilities/provenance, actual runtime from worker health when loaded, a catalog overview with planned entries labeled; managed (speech.cpp) model cache status and an explicit, confirmed delete of one pinned model file.
