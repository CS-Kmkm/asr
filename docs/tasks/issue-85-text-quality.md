Goal: Implement the automatable part of GitHub issue #85: measure AI rewrite quality offline (separate from ASR errors), close the meaning-preservation gaps that deterministic checks can catch, and add opt-in personalization that learns only from edits the user submits.

Scope / non-scope:
- In scope: a correction-only offline dataset of fixed transcript text (Japanese first, plus English and Japanese-English mixed); a deterministic scorer and runner with model-free modes for CI and an app mode that uses the real correction path; guard changes for gaps the dataset shows; opt-in learning from submitted History edits built on the existing dictionary candidates, with scope (app/category, Dictate/Edit/Ask), review, revoke, delete and OFF; Japanese UI strings.
- Non-scope: claims of parity with Typeless or any other product (not measured); human blind evaluation and native Windows UI checks (left to the user); model training; cloud sending of recordings; ASR runtime/model catalog changes (#87: `asr_worker/backends.py`, `src/asr-model-catalog.json`, `src-tauri/src/model_catalog.rs`, ModelsPage untouched); keystroke, screen or full-text collection.

Constraints:
- Synthetic, hand-written text only; no personal recordings or transcripts.
- Generated text is untrusted and never executed; rejected output keeps the existing raw-transcript fallback.
- Learning is off by default, stores only the changed term pair, stores nothing while History is off, and changes nothing until the user confirms a suggestion.
- The app eval mode sends the synthetic transcripts only to the provider its settings select; cloud providers still require the stored consent.

Design:
- Dataset `docs/eval_set/correction/correction-offline-v1.json` (schema `correction-eval/1`): 36 cases (24 ja, 6 en, 6 mixed; conservative and intent-aware) covering fillers, self-corrections, slips, technical terms, negation, numbers/units, URLs/code, long memos and instructions/questions that must not be executed. Each case lists allowed and forbidden changes, `rules.require`/`rules.forbid` span groups by kind, a reference rewrite and fixture outputs (57) with expected scorer failures and an expected guard verdict (`accept`, `reject`, `not_detectable`).
- Scorer/runner `scripts/eval_correction.py`: `validate`, `run --provider identity|reference|fixtures|app`, `score --outputs`, `blind`. Metrics: information dropped/added, names/numbers match, negation preserved, proposition preserved, self-correction resolved, fillers removed, edit ratio. Readability and tone stay `null` (`judge.status: not_scored`) unless a human or LLM judge supplies them. `blind` writes an anonymized CSV sheet and a separate key for human comparison. `app` runs `cargo run --example correction_eval`, which uses the production prompt, transport and guard (`correction::eval`) and records the pre-guard candidate, the guard verdict and the inserted text; the report adds guard catches and false rejections.
- Guard (`correction/polarity.rs`, `correction/fact_check.rs`): both modes reject dropped/added negations (Japanese and English; obligation, hedge and repair-cue phrases masked; a negation followed by a nearby repair cue may be dropped with self-correction on; repeated negated phrases may merge with repetition removal on) and questions turned into statements. Conservative mode additionally compares numbers by value and counter (３/3, 3,000/3000, 三千/3千/3000 equal), URLs and backtick code exactly. Names stay unchecked in conservative mode so spelling fixes remain possible. "actually, make that X" counts as an explicit repair. New metric codes `protected_negation_changed`, `protected_question_changed`.
- Learning (`storage/learning.rs`): setting `personalizationLearning`; command `propose_dictionary_candidate_from_edit(historyId, editedText)` for dictation History rows detects one changed term (cross-script reading such as ぎっとはぶ -> GitHub, or a close same-script respelling) and stores it as a candidate with origin `user_edit`; numbers, unrelated words, hiragana-only grammar, URLs/code and multi-term edits produce nothing. `confirm_dictionary_candidate(id, scope?)` applies app scope and modes; edit suggestions become `learned` entries. `delete_learned_personalization` removes suggestions from edits, learned entries and their decisions. Turning learning off deletes pending edit suggestions in the History policy pass. Schema v5 adds nullable `dictionary_entries.modes` and `dictionary_candidates.origin`; v6 adds `dictionary_candidate_decisions.origin` (older builds ignore them: limited entries apply to every mode, learned entries read as auto). AI-step hints filter by mode; ASR hints do not, because recognition precedes voice-mode routing. Existing suggestions from AI corrections are unchanged.

Acceptance criteria (verify commands run from the repo root unless noted):
1. Dataset schema, fixtures and scorer are reproducible. Verify: `uv run scripts/eval_correction.py validate`; `uv run scripts/eval_correction.py run --provider fixtures` (0 mismatches); `uv run --with pytest pytest asr_worker/tests/test_eval_correction.py`.
2. Rewrites can be compared on the same cases for meaning and (optionally judged) readability. Verify: `run --provider identity|reference`; `run --provider app --settings <patch.json>` against a configured provider; `blind` for human rating.
3. Every fixture marked `reject` is rejected and every reference/`accept` fixture accepted by the production guard. Verify: `cargo test --lib correction` (in `src-tauri`).
4. Learning proposal, scope, confirm, delete and OFF behave as designed, and History OFF stores nothing. Verify: `cargo test --lib storage::learning`; `pnpm test` (`src/test/learning.test.tsx`).
5. No regression. Verify: `uv run --with pytest pytest -q`; in `src-tauri`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test -- --test-threads=4`; `pnpm exec tsc --noEmit`, `pnpm test`, `node --test scripts/test-*.mjs`, `pnpm build`.
