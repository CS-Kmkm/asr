Goal: Begin Phase 2 (#111) by preserving newer clipboard content across an insertion attempt and preventing a paste when the attempt no longer owns the payload.

Scope: Clipboard generation checks around the existing Windows snapshot, write, paste and restore paths, with the same conflict enforced across dictation preview, edit and Ask fallbacks. The first slice uses the Phase 1 baseline and a deterministic clipboard race fixture. Broader strategy, recording and worker changes are subsequent slices.

Baseline: #110 is closed. The reviewed baseline passed mock insertion 6/6, four guards and worker recovery, plus 14/14 real-model insertions. Guest CPU warm Notepad p50/p95 was 10.70/11.58 s (nine trials). Those samples did not exercise a clipboard copy between snapshot and write and cannot establish 99.5% reliability.

The baseline's nine warm Notepad records show ASR spans of 10,453–11,556 ms and paste spans of 42–63 ms. After the input safety regression, CPU recognizer latency is the priority for the latency KPI. - After mock tests, repeat the exact Phase 1 short-fixture real-model run and report warm stop-to-confirmed latency and existing CER/resource metrics against the same conditions. The Phase 2 latency targets are p50 <1.5 s and p95 <2.5 s. Product soak and same-condition competitor runs remain open.

Acceptance for this slice: Capture and publication share a single exclusive clipboard open, with no gap for another writer between them. A copy observed at the final pre-dispatch check must prevent the paste and any copy-only rewrite. A copy before restore must win. An uncontended attempt writes its text once and retains existing confirmation/recovery behavior. Verify with deterministic insertion tests, Windows Rust test suite and independent review. Report VM and competitor evidence separately from this controlled regression.

## Wave A insertion stability

- Dictate, Translate, and Ask caret delivery use the per-app final paste chord in recognized terminals. Live previews stay in the app. Selection replacement retains exact field verification.
- The terminal path reports insertion as unverified. It restores the previous clipboard only after a delayed-rendering request attributable to the target and a matching clipboard owner and sequence. If attribution is unavailable, the final payload stays available. [Terminal clipboard restore](issue-111-terminal-clipboard-restore.md)
- A newer copy detected during cleanup of a failed publication stops automatic retries. Restore attempts every captured format and reports format publication or close errors. A live preview that loses its guard before publication writes nothing. If a preview was staged and dispatch is declined, cleanup restores the previous clipboard subject to the sequence check, including when restoration is disabled for successful pastes.
- The regression fixtures exercise terminal dispatch, newer-copy conflicts, restore failures, and rejected previews with simulated targets. The ASR-Eval receivers confirmed delivery in Windows Terminal, mintty, and PuTTY. [Phase 2 evidence](issue-111-phase2.md)
- The opt-in direct transports distinguish declined, fully dispatched, and ambiguous sends. Full and ambiguous dispatches both require exact field readback to claim delivery. Only a declined send can proceed through the clipboard.
